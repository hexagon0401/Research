# v2.4.1 — 그림과 설명을 함께 읽기

2026-10-23. 기준 v2.4.0 `429de98`. 앱은 기존 `v1.1.0/`, Vercel Hobby·Supabase Free 구성을 유지한다.

## 변경

- 모든 12개 애니메이션 도식에 CSS sticky를 적용했다. 데스크톱에서는 왼쪽 그림과 오른쪽 설명, 작은 화면에서는 탐색 막대 아래의 축소 그림과 세로 본문을 사용한다. GSAP pin은 제거했다.
- 설명 단계의 실제 문서 위치로 진행률을 계산한다. 날짜·현재 단계·선·지도는 같은 읽기 위치를 따른다. 마지막 단계에는 완성 그림을 볼 읽기 거리를 남긴다. 확대·창 크기·상세 펼침·글꼴 변경 시 경계를 다시 측정한다.
- 그린란드·미얀마·캄보디아를 하나의 연속 지도로 묶었다. 18개 논지 주소와 기존 문단 주소를 유지하며, 중복 그림을 줄여 독립 그림은 16개다.
- 기존 Natural Earth 투영의 국가 경계와 지점 범위로 지역을 확대한다. 북극 지도는 별도 투영으로 유지한다. HTML 지명과 선 굵기는 카메라 확대와 분리했다. 비교 단계에서도 지역을 선택해 다시 확대할 수 있다.
- 선택 상태는 Paper/Ink·밑줄·작은 Signal 점으로 표시한다. 모바일 지도 위 도구를 줄이고, 확대 대화상자는 현재 장면을 정적으로 복사한다. Escape·닫기 후 초점과 스크롤 위치가 돌아온다.
- 메인·도식의 한영 편집 설명을 제목·핵심 설명·항목·연결 문장으로 다시 작성했다. 질문과 결론에 저자의 목소리를 담고, 제작 보고 문구를 걷어냈다. 긴 논증·원문 발췌·출처는 native details로 펼쳐 읽는다. 원문에서 돌아오면 펼침 상태와 위치도 복원한다.
- 공통 푸터에 요청한 Kennedy 인용을 추가했다. 이는 사용자가 제공한 문구이며 이번 릴리스에서 연설 원자료의 출전·날짜를 새로 검증한 인용은 아니다.

## 보존

`essay.ts`와 `research-connections.ts`는 편집 설명으로 명시적으로 분리했다. `audit:preservation`의 이 두 파일만 허용 목록에 넣고, 연구 전사·영어 전문·문단 ID·API·백엔드·PDF/미디어 잠금은 유지한다. 13개 연구·973개 대응 문단과 기존 PDF 해시를 보존한다. 사례의 새 항적·시설 경계·수송 사실·통계 결과는 추가하지 않았다.

## 검증

Node.js 24.19.0, Next.js 16.4.2 production build와 Linux Chromium을 사용한다. 실제 운영 주소 확인과 로컬 자동 검사를 구분해 아래에 기록한다.

- `npm run build`, `npm run typecheck`, `npm test`: 운영 빌드·타입·26개 콘텐츠/좌표/원문 연결 검사 통과.
- `audit:readings`, `audit:preservation`: 13개 전문·973개 대응 문단·원문 문자·번역 지문·기존 API/백엔드 보존, PDF 13개 SHA-256 일치.
- `format:check`, `git diff --check`: 통과.
- 전체 Chromium 회귀 204항목: 175개 통과, 28개 환경 조건부 제외. 새 엔진 실패 검사 1개가 hydration 전에 입력해 실패하여, 측정 준비 상태를 기다리도록 검사 하네스를 수정했다. 아래 최종 실행에서 같은 검사를 통과했다.
- 최종 보완 빌드의 관련 회귀 40항목: **29개 통과·11개 조건부 제외·실패 0**(1.2분). 모든 12개 도식의 0/25/50/75/100% 고정, 일곱 중국 단계의 날짜 일치, 실제 휠 정·역방향, 중단 가능한 재생, 원문 복귀, 지역 확대/비교 선택, 모션 감소·엔진 실패, 확대 대화상자 초점/스크롤 잠금, 낮은 높이와 CSS 200% 확대를 확인했다.
- 320~1920px 한영 폭, 원문 펼침과 직접 문단 주소, 뒤로 가기·언어 전환, No-JS, 큰 PDF의 페이지/확대/전체화면/다운로드 해시는 전체 회귀에서 확인했다.
- Chromium CDP 터치 드래그로 진행률 **0.3201→0.3829**, 단계 2를 관측했다. 그림은 상단 **70px~327.7px**에 유지됐다(390×844). 이후 목차에서 한국어로 전환하고 캄보디아 단계 4·같은 그림 위치를 확인했다. 키보드 초점 상태와 한영 화면을 직접 캡처해 대조했다.
- 제목 순서 감점을 수정한 최종 빌드는 아래 Lighthouse 접근성 **100점**이다. 이 제목 태그 교정 후 전체 204항목을 다시 실행했다고 주장하지 않는다.

### 모바일 Lighthouse

기본 모바일·시뮬레이션 제한, production 서버에서 브라우저 회귀 종료 후 독립적으로 3회 측정했다. [측정 요약 JSON](validation/v2.4.1-lighthouse.json)에 원시 수치를 보관한다.

| 회차   | 성능   | 접근성  | 권장사항 | LCP   | TBT   | CLS |
| ------ | ------ | ------- | -------- | ----- | ----- | --- |
| 1      | 88     | 100     | 100      | 3.18s | 264ms | 0   |
| 2      | 90     | 100     | 100      | 3.03s | 229ms | 0   |
| 3      | 89     | 100     | 100      | 3.03s | 259ms | 0   |
| 중앙값 | **89** | **100** | **100**  |       |       |     |

**성능 목표 95점은 미달**이다. 접근성 100점은 충족했다. `audit:performance`의 95점 기준을 유지하므로 이 명령은 실패 종료한다. 초기 메인 전송량은 약 452KB이며, 클라이언트 콘텐츠/수화 비용과 시뮬레이션 LCP는 후속 최적화 과제다. GSAP·PDF·워커·보고서 API를 초기 메인에서 불필요하게 내려받지 않는 구조를 유지했다. 이 수치는 원격 운영 사이트의 Core Web Vitals나 실기기 성능을 보장하지 않는다.

### 운영 확인

커밋 푸시 후 운영 주소의 반영 상태와 실제 확인 범위를 여기에 기록한다.

## 재현

```sh
npm ci
npm test
npm run audit:readings
npm run audit:preservation
npm run build
npm run typecheck
npm run format:check
E2E_BASE_URL=http://127.0.0.1:3000 CHROME_PATH=/usr/bin/chromium npm run test:e2e
AUDIT_URL=http://127.0.0.1:3000 CHROME_PATH=/usr/bin/chromium npm run audit:performance
```

운영 서버는 별도 터미널의 `npm run start`로 실행한다. Lighthouse는 브라우저 회귀 검사 종료 후 독립적으로 실행한다. 원문·영어 전문의 저자 최종 검수 상태는 이전과 같다. Linux Chromium의 터치 에뮬레이션은 실제 iOS Safari 기기 검사를 대신하지 않는다.
