# 연속 스크롤·커서 인터랙션 개편 실행 계획

2026-10-22 후속: 이 계획을 기반으로 v2.0.0의 공통 스크롤 엔진·연속 진행선·궤도와 행 강조·지도 탐색·선택 고정·네이티브 입력을 구현했다. 아래는 작성 당시의 전체 설계이며, 현재 실제 구현·검증 범위는 [v2.0.0 기록](V2_RELEASE.md)을 따른다.

작성: 2026-10-21 · 포함 릴리스: 1.1.2 · 상태: **설계와 검증 기준 확정, 구현 전**

이 문서는 다음 개발 단계의 구현 명세다. 1.1.1의 화살표 수정, 1.1.2의 원문 아카이브와 구분한다. 아래에 적힌 애니메이션·성능 수치를 이번 릴리스에서 구현하거나 실측한 것으로 표시하지 않는다. “오류 없음”이라는 보증 대신 실패 조건과 통과 기준을 명시한다.

현재 메인에 세로 `scroll-snap`은 없다. 따라서 존재하지 않는 스냅 옵션을 제거하는 처방을 쓰지 않는다. 단절의 주원인은 구획·여백·독립적인 배경과 정적인 도식이다. CSS의 `scroll-behavior: smooth`는 앵커 이동의 보간이며 스크롤 연동 애니메이션 구현을 대신하지 않는다.

## 2. 시각·입력 원칙

1. 문서는 브라우저의 기본 세로 스크롤을 사용한다. wheel/touchmove를 취소하거나 별도의 가상 스크롤 위치로 대체하지 않는다. PageDown, Space, Home/End, 앵커, 뒤로 가기가 그대로 작동해야 한다.
2. 시각 언어는 기존 종이색·잉크색과 강조색 **선**이다. 새 사진 배경, 3D 입자, 복잡한 캐릭터, WebGL/Canvas 전용 장면을 도입하지 않는다.
3. 본문은 항상 제자리에 읽을 수 있어야 한다. 긴 문단의 패럴랙스·흐림·글자 분해·마스크 가림을 사용하지 않는다. 이동은 장식과 짧은 레이블에 한정한다.
4. 마우스 포인터는 기본 커서를 유지한다. 링크는 링크, 버튼은 버튼으로 보이고, hover로 발견한 정보에는 동일한 focus·click·touch 경로가 있어야 한다.
5. 모션이 없거나 JavaScript가 실패해도 텍스트·지도 설명·자료 링크는 완전하게 남는다. 기본 CSS가 본문을 `opacity:0`으로 숨기지 않는다.
6. 가설선과 관측 근거를 혼동하지 않는다. 점선은 가설/제안, 실선은 탐색 연결 또는 실제 출처 이동이다. 움직이는 선을 검증된 인과나 실제 군사·상업 거래의 표시로 사용하지 않는다.

## 3. 끊김 없는 페이지 구조

### 3.1 연속된 읽기 축

- 메인 전체에 하나의 읽기 축을 둔다. 1200px 이상에서는 콘텐츠 왼쪽 여백에 1px 기준선과 2px 강조선이 함께 지나가고, 좁은 화면에서는 본문 상단의 짧은 진행선으로 축소한다.
- 거대한 세로 SVG 한 개를 페이지 전체에 펼치지 않는다. 각 챕터 안의 짧은 SVG/직선 구간이 동일한 `--thread-x`에서 끝나고 다음 구간에서 이어지게 한다. 장식 레이어는 `pointer-events:none`, `aria-hidden=true`, 제한된 크기와 부모 경계를 갖는다.
- 중간의 여백도 다음 챕터의 시작선과 작은 질문 라벨로 연결한다. 도식이 끝난 뒤 빈 화면을 하나 더 스크롤하게 만드는 인위적인 spacer를 넣지 않는다.
- 색상 전환은 챕터 시작의 얇은 띠와 넓은 중립 배경에서 처리한다. 검은 패널을 화면마다 별도 카드로 반복하지 않는다. 본문 아래에 움직이는 색상 면이나 대비가 낮아지는 중간 상태를 두지 않는다.
- 섹션 높이는 콘텐츠와 `clamp()` 간격으로 결정한다. 본문에 `height:100vh`를 강제하지 않는다. Hero만 최소 높이를 갖고, 모바일 주소창을 고려해 `svh`를 사용한다.
- 주요 헤딩과 다음 챕터 제목이 같은 화면의 경계에서 일부 함께 보이도록 연결한다. 단, 글자를 자르거나 읽기 영역을 가리는 연출로 예고하지 않는다.

### 3.2 읽기 순서

질문 → 비교 대상 → 기업의 역량 → 확보한 근거와 한계 → 메커니즘 가설 → 조건부 제안 → 원문 자료로 이어진다. 기존 ID `question`, `world`, `corporations`, `evidence`, `framework`, `synthesis`, `index`와 문서·자료 URL을 유지한다. 주소에 이미 있는 해시나 `?scene=`로 들어와도 해당 위치가 읽기 상태로 바로 표시되어야 한다.

### 지도와 다이어그램의 크기 규칙

- SVG에는 `viewBox`, `width`, `height`를 명시한다. 부모는 `minmax(0, …)` 열, SVG는 `max-width:100%; height:auto`를 갖는다.
- 노드의 시각 반경과 조작 영역은 분리한다. 작은 점이 보여도 실제 버튼 영역은 44×44 CSS px 이상이다.
- 뷰포트·언어가 바뀌면 측정값을 폐기하고 다시 계산한다. 이전 영어 레이아웃 좌표를 한국어에 재사용하지 않는다.
- 선 길이는 초기화/레이아웃 변경 시만 측정한다. 매 프레임 `getTotalLength()`를 호출하지 않는다.
- 다이어그램의 편집 레이블은 원문 주장과 구분한다. 실제 자료가 없는 국가·기업·계약의 가상 경로를 넣지 않는다.

## 5. 상태·이벤트 설계

### 5.1 하나의 스크롤 상태

중앙 `ScrollNarrative`가 활성 챕터와 진행률을 계산하고 Progress·Orbit·Framework가 같은 상태를 읽는다. 중복 rAF와 챕터마다 별도의 scroll listener를 만들지 않는다.

- 전체 진행률: `clamp(scrollY / (documentHeight - viewportHeight), 0, 1)`. 분모가 0 이하이면 0으로 둔다.
- 챕터 진행률: `clamp((viewportHeight - rect.top) / (rect.height + viewportHeight), 0, 1)`. 진입 전 0, 완전히 지난 뒤 1이다.
- 현재 챕터는 화면의 35% 지점을 포함하는 구간으로 정한다. 여러 IntersectionObserver callback의 순서에 따라 마지막 항목을 선택하지 않는다. 문서 끝에서는 마지막 챕터를 유지한다.
- IntersectionObserver는 화면 근처 구간을 깨우는 용도로만 사용한다. 정밀 진행률은 단일 렌더 루프에서 계산한다.
- React state를 모든 픽셀 변화에 갱신하지 않는다. 연속 값은 DOM ref와 CSS custom property로 쓰고, React 상태는 챕터/선택 상태가 바뀔 때만 갱신한다.
- read 단계에서 필요한 rect를 읽고 write 단계에서 transform/선 상태를 적용한다. 같은 프레임에 스타일 쓰기와 강제 레이아웃 읽기를 섞지 않는다.

### 5.2 CSS와 JavaScript의 역할

CSS scroll-driven animation은 지원 확인 뒤 장식에만 사용한다. 지원하지 않는 Safari·Firefox 경로에는 rAF 대체를 사용하되 같은 요소에서 두 엔진이 동시에 실행되지 않게 한다. 브라우저 지원을 가정한 CSS 때문에 기본 상태가 사라지지 않도록 정적 스타일을 먼저 정의한다.

상태는 `static` / `enhanced` / `reduced` 세 가지다. 향상 초기화가 실패하면 `static`으로 돌아간다. `visibilitychange`에서 보이지 않는 탭의 루프를 멈추고, 다시 보이면 현재 실제 스크롤 위치에서 재계산한다. 뒤로 가기와 bfcache의 `pageshow`도 같은 초기화를 사용한다.

### 5.3 일시 미리보기와 고정 선택

Atlas와 Framework에는 `previewId`와 `selectedId`를 분리한다. 포인터가 떠나거나 focus가 빠지면 preview만 해제하고, 클릭으로 고정한 선택은 유지한다. Escape는 고정 선택을 해제하되 기본 페이지 스크롤을 임의 위치로 되돌리지 않는다. 설명 영역의 크기는 콘텐츠가 가장 긴 언어를 기준으로 충분히 잡아 hover 시 주변 문단이 뛰지 않게 한다.

스크롤로 제안한 활성 노드와 사용자가 선택한 노드가 충돌하면 **사용자 선택을 우선**한다. 별도의 “읽기 흐름 따라가기” 버튼을 누를 때만 자동 강조를 다시 연결한다. 이 상태는 실제 연구 데이터의 필터나 주장 자체를 바꾸지 않는다.

### 5.4 기존 제스처 정리

- `ArchiveGesture`의 window-level non-passive wheel listener를 제거한다. 트랙패드의 가로·대각선 움직임으로 아카이브에 강제 이동하지 않는다.
- 서가 안에서는 브라우저의 `overflow-x:auto`를 사용한다. 포커스가 서가에 있을 때만 좌우 키를 처리한다.
- A 단축키를 유지한다면 안내와 명시적 포커스 범위를 둔다. 입력칸·텍스트 선택·IME 조합·Ctrl/Meta/Alt·브라우저 찾기에는 반응하지 않는다. 최소한 `event.isComposing`을 검사한다.
- 링크 이동 후 자동 포커스는 제목/주요 콘텐츠처럼 예측 가능한 대상에 한정한다. 스크롤 중에는 문서 포커스를 옮기지 않는다.

| 폴더 이동        | 최대 4px, 회전 최대 2°, text blur와 perspective 텍스트 왜곡 금지                     |
| 읽기 텍스트      | 이동 0px, blur 0, 숨김 없음                                                          |
| 고정 다이어그램  | 넓은 화면의 보조 열에만 `position:sticky`; 본문은 계속 흐름                          |
| 레이아웃 예산    | 모션으로 인한 CLS 0 목표. 전체 페이지 CLS 목표 ≤0.1                                  |
| 프레임           | 60Hz 환경에서 16.7ms/frame 예산. JS callback 목표 p95 ≤4ms                           |
| idle             | 정지 상태·숨겨진 탭에서 지속 rAF 0개                                                 |
| 추가 전송        | 메인 모션용 초기 JS 증가 목표 ≤20KB gzip, 대형 모션 라이브러리 기본 도입 안 함       |
| 데이터/파일      | 원문 전체·PDF·도표를 메인에서 prefetch하지 않음. 실제 자료 화면과 클릭 이후에만 로드 |

픽셀마다 layout 속성인 top/left/height/width를 애니메이션하지 않는다. SVG dash/opacity·transform 위주로 구현한다. `will-change`는 활성 장식에만 일시적으로 적용하고 긴 페이지 전체를 GPU 레이어로 승격하지 않는다. 배경 전환을 위한 대형 blur/backdrop-filter를 추가하지 않는다.

## 7. 반응형·접근성 규칙

| 조건                               | 동작                                                                   |
| ---------------------------------- | ---------------------------------------------------------------------- |
| ≥1200px, 높이 ≥720px, fine pointer | 왼쪽 진행축, 보조 열 sticky, 제한된 커서 반응                          |
| 900–1199px 또는 낮은 화면          | 진행축 축소, sticky는 실제 남는 높이가 충분할 때만 활성                |
| <900px / coarse pointer            | 단일 열, 보조 패널 sticky 해제, hover 연출 해제, 터치 버튼 유지        |
| 200% 확대 / 320 CSS px 폭          | 두 방향 동시 스크롤 요구 금지. 표·코드는 자체 영역만 가로 이동         |
| OS 모션 감소                       | CSS 미디어쿼리가 첫 페인트부터 모션 차단. JS 준비 전에도 적용          |
| 사이트의 모션 줄이기 ON            | 저장 후 이동·새로고침에도 유지. 선·노드 정적 상태로 모든 정보 제공     |
| JavaScript 비활성                  | 본문/원문 링크/정적 지도 설명/문서 목차 유지                           |
| 키보드만 사용                      | 명확한 focus ring, 모든 선택 버튼·노드·원문 링크 접근, focus trap 없음 |
| 스크린리더                         | 장식 SVG 숨김, 활성 챕터는 과도한 aria-live 알림 대신 현재 위치 표시   |

모션 감소 설정의 우선순위를 명시한다. OS 감소 요청이 있으면 기본으로 감소하고, 초기 hydration의 `data-motion=full` 때문에 잠깐 모션이 켜지지 않아야 한다. 동작을 켜는 설정을 허용하더라도 사용자가 명시적으로 선택한 경우에만 적용한다. 초기 상태와 저장 값·미디어쿼리의 조합을 별도 테스트한다.

선택 상태는 색만으로 표시하지 않는다. 텍스트, 선 굵기, `aria-pressed` 또는 해당 widget에 적합한 상태 속성을 함께 사용한다. 실선/점선 범례와 출처 상태는 항상 읽을 수 있어야 한다. 포인터 좌표를 수집·저장하거나 외부로 보내지 않는다.

## 8. 콘텐츠·자료 연동

- `/reports`와 `/reports/[id]`는 모션과 독립적인 HTML 원문 열람 경로다. 메인 장면이 실패해도 접근 가능해야 한다.
- Evidence에서 확보한 원문 ID와 “원시 데이터/코드 미확보” 상태를 동시에 보여준다. 전사 완료를 분석 재현 완료로 바꾸지 않는다.
- S03과 S13은 서로 다른 Golden Dome 파일이다. 한 장면의 숫자나 문장을 둘 중 임의 원문에 붙이지 않는다.
- S04·S07·S09·S10·S12 미제공 상태를 유지한다. 새 S14–S17을 이름만 비슷한 기존 자료로 덮어쓰지 않는다.
- 문단/쪽 링크에는 실제 source ID와 locator를 사용한다. 계획 발췌 P-001–P-006과 원문 locator를 같은 ID로 혼용하지 않는다.
- PDF는 서명 링크를 클릭 시 발급한다. 서명 링크를 정적 HTML·Git·분석 로그에 저장하지 않는다.
- 한국어/영어 UI 전환은 탐색 문구만 바꾼다. 원문 한국어를 자동으로 영어 검수 번역으로 표시하지 않는다.

## 10. 검증 매트릭스

### 필수 자동 검사

1. 프로덕션 빌드·TypeScript·콘텐츠 무결성·출처 해시/locator 검사 통과.
2. 320, 375, 390, 768, 900, 1024, 1200, 1440, 1760, 1920px 너비. 568/720/900/1080px 높이의 대표 조합에서 EN/KO 확인. 모든 조합을 실기기라고 표현하지 않는다.
3. 메인 최상단·모든 섹션 중간·경계±1px·최하단에서 활성 챕터와 진행률 범위 [0,1] 확인. 문서 높이가 뷰포트보다 작을 때 NaN 없음.
4. 휠/터치/키보드 PageDown·Space·Home·End가 자연스럽게 이동. 세로·대각선 휠이 아카이브를 열지 않음.
5. 지도/Framework hover→leave, focus→blur, click→scroll, Escape, 두 번 빠른 선택에서 선택 상태 일관성.
6. `/#synthesis`, `/?scene=framework`, 원문 문단 해시 진입과 새로고침. 뒤로/앞으로 이동 시 스크롤·폴더·선택 복원.
7. 초기 저장 값 없음/감소 true/감소 false와 OS reduce/no-preference 조합. 실행 중 OS 변경도 확인. reduced에서 transform 애니메이션·지속 rAF 없음.
8. JavaScript OFF, localStorage 접근 거부, 폰트 로드 지연/실패, SVG 길이 측정 실패, 탭 숨김/복귀, 빠른 연속 resize를 주입해 본문과 링크 유지 확인.
9. 모든 SVG 경계가 부모 영역 안에 있고 본문/링크를 덮지 않음. 클릭 대상 중심점의 `elementFromPoint`가 장식이 아님. 1.1.1 synthesis 회귀 검사 유지.
10. axe WCAG 2A/AA·2.1A/AA 검사에 모션 활성/정적/감소 상태를 포함. 검사 통과를 스크린리더 실사용 검증으로 바꾸지 않음.

### 브라우저·실기기 확인

Chromium, Firefox, WebKit 자동화에 더해 macOS Safari와 실제 iOS Safari/Android Chrome에서 긴 페이지 스크롤을 확인한다. Playwright WebKit 통과를 실기기 Safari 통과로 쓰지 않는다. 사용할 수 없는 기기는 미확인으로 남긴다. VoiceOver 또는 NVDA에서 목차·지도 선택·원문 이동을 확인하고 실제 사용한 조합만 기록한다.

### 성능 확인

프로덕션 서버에서 다른 빌드/브라우저 작업 없이 Lighthouse mobile을 3회 실행하고 중앙값·최악값을 함께 기록한다. LCP ≤2.5s, CLS ≤0.1, 필드 INP ≤200ms를 목표로 삼되 랩 TBT를 실제 사용자 INP로 부르지 않는다. CPU 4× slowdown에서 스크롤 trace를 수집해 scripting·layout·paint·장기 작업을 확인한다. 첫 방문과 재방문, 폰트 지연을 분리한다. PDF·전사 전문·도표가 메인 초기 네트워크에 포함되지 않는지 확인한다.

성능 예산 초과 시 순서대로 포인터 이동 제거 → dash 업데이트 빈도 축소 → sticky 장식 축소 → 정적 상태 전환을 적용한다. 정보나 접근 경로를 없애서 성능 검사를 통과시키지 않는다.

## 11. 회귀·출시 기준과 복구

릴리스 조건은 필수 자동 검사 통과, 사용자 입력 가로채기 없음, 본문 가림 없음, 원문/연구 상태 보존, 실제 성능 결과 기록이다. 해결되지 않은 오류나 미확인 플랫폼은 명시하고 완료로 위장하지 않는다.

모션 기능은 UI 환경설정과 독립적인 단일 향상 모드 스위치로 비활성화할 수 있게 설계한다. 문제가 있으면 애니메이션 모듈만 끄고 같은 HTML 문서와 자료실을 유지한다. 콘텐츠·원본 객체·자료 ID를 되돌리거나 삭제하는 방식으로 모션 오류를 해결하지 않는다. Git 태그 1.1.1/1.1.2와 이후 모션 구현 커밋을 분리해 원인 추적과 선택적 revert가 가능하게 한다.

## 12. Open Design 인계 계약

인계에는 컴포넌트 목록, 토큰, 각 상태의 EN/KO 화면, desktop/mobile/reduced/static 비교, source/claim 의미, SVG 크기 제약, 성능 trace, 접근성 결과를 포함한다. 디자이너가 조정할 항목은 색·간격·선 굵기·짧은 장식 이동량이다. 변경하면 안 되는 항목은 원문 문자열·자료 ID·해시·검증 상태·공개 권한·키보드 경로다.

구현 완료 후에만 실제 스크린 녹화와 측정 수치를 추가한다. 설계 시점에 가상의 시연·테스트·프레임 수치를 만들지 않는다.
