# IIR 원본 열람·상시 공개 운영 계획

작성일: 2026-10-21 · 상태: 무료 플랜 구현 진행

> 최신 사용자 제약: 비용 0원, 유료 전환 금지. 아래 초기 구상 중 유료 운영 제안은 실행 대상에서 제외합니다. GitHub의 최신 v1.1.0 디자인에 원본 연결 기능을 준비했고, 현재 설정·검증·사용자 계정 작업은 [무료 실행 안내](../v1.1.0/docs/FREE_LAUNCH.md)를 우선합니다. Vercel Root Directory도 v1.1.0을 사용합니다.

## 1. 추천안

**사이트는 Vercel, 연구 원본은 Supabase Storage에 보관합니다.** 처음에는 GitHub 연동 배포와 Supabase 대시보드의 수동 업로드를 이용합니다. 방문자 회원가입과 별도 웹 관리자 화면은 초기 범위에서 제외합니다.

| 구성                          | 용도                                           | 선택 이유                                                                        |
| ----------------------------- | ---------------------------------------------- | -------------------------------------------------------------------------------- |
| GitHub `hexagon0401/Research` | 사이트 코드·공개 메타데이터·변경 이력          | 기존 저장소 재사용, 배포 버전 추적                                               |
| Vercel                        | Next.js 사이트·원본 열람 링크 발급용 서버 함수 | 현재 App Router 코드와 맞으며 HTTPS·배포·도메인 운영을 관리형으로 시작 가능      |
| Supabase Storage              | PDF 열람본·HWP/HWPX/DOCX 등 원본 파일          | 파일을 코드와 분리하고 공개 승인 상태에 따라 접근 제어                           |
| Supabase Postgres             | 문서·파일 버전·프로젝트 연결·공개 상태         | 한 원본을 여러 연구 장면에 연결하고 철회·교체 상태 관리                          |
| Oracle Cloud                  | 후속 대용량 변환·OCR·배치 작업 후보            | 장시간 작업이나 서버 자원이 필요해질 때 검토. 초기 사이트 운영에는 추가하지 않음 |

Vercel 사이트는 개인 PC를 계속 켜두지 않아도 접속할 수 있게 배포합니다. 상시 실행되는 개발 서버를 공개하는 방식이 아니라, 정적 페이지와 필요한 요청별 서버 함수를 이용합니다. 서비스 가용성은 선택한 요금제·할당량·제공자의 운영 상태에 따릅니다.

현재 요청은 계획 수립입니다. 이 문서 작성으로 외부 계정 생성·과금·배포·파일 업로드·공개 승인이 이루어지지 않았습니다.

## 2. 방문자가 경험할 흐름

1. 연구 리더에서 `원본 보기 / View original`을 선택합니다.
2. 연결된 문서가 여러 개이면 제목·자료 ID·버전·파일 형식·용량을 보고 선택합니다.
3. 사이트 서버가 해당 파일이 **공개 승인된 현재 버전**인지 확인합니다.
4. 서버가 짧은 유효기간의 Supabase 서명 링크를 발급하고 파일 주소로 이동시킵니다.
5. PDF는 새 탭의 브라우저 PDF 뷰어로 열립니다. 브라우저가 지원하지 않으면 다운로드 경로를 제공합니다.
6. HWP/HWPX/DOCX 등의 작성 원본은 별도 `작성 원본 다운로드` 링크를 제공합니다.

서명 링크의 제안 유효기간은 5분입니다. 이미 열린 파일의 이어 읽기·브라우저 Range 요청에 문제가 있는지 실제 PDF로 확인한 뒤 조정합니다. 링크가 만료되면 사이트에서 새 링크를 받을 수 있게 합니다.

파일 바이트는 Supabase에서 방문자에게 직접 전송합니다. Vercel 함수는 공개 상태 확인과 링크 발급만 담당하므로 PDF 전체를 함수가 중계하지 않습니다. 파일은 클릭 시 요청하고 홈페이지 첫 화면에서 PDF를 미리 내려받지 않습니다.

서명 링크는 유효기간 동안 전달받은 사람도 이용할 수 있고, 방문자가 이미 저장한 사본을 회수하지는 못합니다. 따라서 **누구에게나 보여도 되는 자료만 익명 방문자에게 발급**합니다. PDF 브라우저 열람 역시 다운로드 방지를 의미하지 않습니다.

## 3. ‘원본’의 구분

| 파일 유형     | 보관·열람 정책                                                                 |
| ------------- | ------------------------------------------------------------------------------ |
| 작성 원본     | 업로드한 파일의 바이트와 SHA-256을 보존. HWP/HWPX/DOCX/PDF 등 실제 형식 명시   |
| PDF 열람본    | 작성 원본을 변환한 별도 파생본. 변환 일자와 원본 연결 기록                     |
| 공개용 사본   | 개인정보 삭제 등이 있으면 ‘공개용 사본’으로 표시하고 수정 사실 기록            |
| 미공개 원본   | 원본에 개인정보·공동저자 정보·공개할 수 없는 자료가 있으면 관리자만 보관·접근  |
| 외부 참고문헌 | 재배포 허용 여부가 확인되지 않으면 원문 저장 대신 합법적인 공식 출처 링크 제공 |

원본을 수정한 파일을 수정 전 원본이라고 표시하지 않습니다. 원본 그대로 공개할 수 있는 파일은 그 원본을 제공하고, 수정이 필요한 파일은 공개용 사본과 비공개 작성 원본을 구분합니다.

**현재 실제 확보한 자료는 사이트 명세와 연구 통합 작업계획 두 파일입니다.** 작업계획에 기재된 S00–S12 연구 원문은 이 저장소에 제공되지 않았습니다. 계획 파일을 실제 연구 보고서로 업로드하거나 없는 원문 링크를 생성하지 않습니다.

## 4. Storage·공개 상태 설계

### 버킷

두 버킷 모두 비공개로 시작합니다.

- `research-originals`: 보존용 작성 원본. 익명 서명 링크 발급 대상에서 제외합니다.
- `research-reader`: 공개 검토를 마친 PDF 및 작성 원본의 공개 가능 버전. 공개 승인된 DB 항목에 대해서만 서명 링크를 발급합니다.

폴더 예: `S06/rev-001/reader.pdf`, `S06/rev-001/source.hwpx`. 개인정보가 담긴 실제 이름을 공개용 경로에 넣지 않습니다. 신규 버전은 `rev-002`처럼 새 경로에 추가하고 기존 파일을 덮어쓰지 않습니다. 공개 가능한 작성 원본을 두 버킷에 보관할 경우 해시로 같은 파일인지 확인합니다.

### 최소 데이터 모델

- `documents`: 자료 ID, 제목, 공개용 파일명, 언어, 자료 유형.
- `document_versions`: 버전 ID, 문서 ID, 작성·업로드 시점, 원본/변환본 관계, 편집·변환 메모.
- `document_assets`: 버전 ID, 자산 유형, 버킷, 객체 경로, MIME, 바이트 크기, SHA-256, 공개 상태, 권리 검토 상태, 공개 승인 일시.
- `project_documents`: 사이트의 여섯 연구 프로젝트와 실제 원문 문서의 연결. 동일 S06 원본이 여러 장면에 연결되더라도 중복 업로드하지 않음.

공개 상태는 `draft / published / withdrawn`으로 관리합니다. **파일 공개 승인과 연구 주장의 사실 검증 상태는 별도 필드**입니다. 공개된 보고서도 분석이 재현되지 않았다면 해당 사실을 유지합니다.

공개 API는 열람에 필요한 메타데이터만 반환합니다. 비공개 원본 파일명·스토리지 경로·미공개 문서 레코드는 노출하지 않습니다.

### 권한

- 방문자: 공개 메타데이터 조회와 승인된 파일 링크 요청만 가능. 익명 업로드·수정·삭제 권한 없음.
- 관리자: 초기에는 Supabase 대시보드에서 업로드·메타데이터 등록·공개 승인.
- Vercel 서버: 승인 상태를 확인한 뒤 `research-reader` 파일만 서명.
- 브라우저: 관리자용 비밀 키를 받지 않음.

테이블과 `storage.objects`에는 필요한 RLS 정책만 적용합니다. 서버용 비밀 키 또는 legacy `service_role`은 RLS를 우회할 수 있으므로 **RLS만으로 서버의 서명 대상을 제한했다고 가정하지 않습니다**. 서버 코드에서 버킷·공개 상태·자료 ID를 명시적으로 검증합니다. 요청에서 임의 버킷·객체 경로를 받지 않습니다.

초기에는 로그인 없는 공개 열람을 유지합니다. 일부 독자에게만 미공개 자료를 공유해야 한다면 별도 인증·허가 기능을 후속으로 설계합니다.

## 5. 현재 사이트에서 필요한 개발

기준 코드는 `v1.0.0/`입니다. 이 버전은 보존하고, 구현 요청이 오면 후속 버전(가안 `v1.1.0/`)에서 변경합니다. 현재 계획만으로 후속 폴더를 생성하지 않습니다.

| 변경              | 현재 상태                        | 구현 후                                               |
| ----------------- | -------------------------------- | ----------------------------------------------------- |
| Reader 원본 버튼  | `ORIGINAL PDF NOT SUPPLIED`      | 원문이 연결되고 공개 승인된 경우에만 실제 링크 표시   |
| 문서 연결         | 여섯 Phase의 계획 발췌문         | 실제 S00–S12 원문과 1:N 연결                          |
| 출처 레일         | 계획 문서 위치·미확보 상태 표시  | 원본 버전·원문 위치·파일 형식·해시 메타데이터 연결    |
| 원본 링크 발급    | 없음                             | `GET /api/public/assets/[assetId]/open` 서버 경로     |
| 파일 데이터       | 공개 JSON·어댑터                 | 기존 연구 JSON 유지 + 원본 자산용 서버 전용 DB 어댑터 |
| 사이트 메타데이터 | 초안 `noindex`, 공개 도메인 미정 | 검토 완료 뒤 실제 도메인·canonical·sitemap 설정       |

서명 경로는 요청마다 최신 공개 상태를 조회하고 `Cache-Control: private, no-store`를 적용합니다. 서명 링크를 영구 저장하거나 CDN의 공용 응답으로 캐시하지 않습니다. 링크 발급 오류와 Supabase 휴면·장애는 구분해 표시하고, 원본을 열 수 없어도 기존 HTML 내러티브·방법론·문서 본문은 읽을 수 있도록 유지합니다.

비밀 키를 쓰는 모듈은 서버 전용으로 분리합니다. 예시 환경 변수는 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`이며 실제 키 종류는 프로젝트가 제공하는 현행 키 체계에 맞춥니다. 서버용 키에 `NEXT_PUBLIC_` 접두사를 쓰지 않습니다. 키 값은 Vercel의 환경 변수 설정에 입력하며 GitHub·계획 문서·채팅에 기록하지 않습니다. 읽기 전용 브라우저 클라이언트가 필요해질 때만 별도의 공개 키와 RLS를 구성합니다.

## 6. 실행 순서와 완료 조건

### 단계 A — 기존 사이트부터 공개 테스트

사용자가 할 일:

1. Vercel에 GitHub 계정으로 로그인합니다.
2. 프로젝트 추가/Import에서 `hexagon0401/Research`를 선택하고 이 저장소에 대한 접근을 허용합니다.
3. Root Directory를 **`v1.0.0`**으로 설정합니다.
4. Framework는 Next.js, Install Command는 `npm ci`, Build Command는 `npm run build`를 사용합니다. Output Directory는 Next.js 기본값을 유지합니다.
5. 로컬 검증에 사용한 Node.js는 24입니다. Vercel이 제공하는 지원 버전 목록에서 24.x 가용성을 확인합니다. 없으면 지원되는 LTS로 테스트한 뒤 배포합니다.
6. Deploy 후 생성된 서비스 주소를 시크릿 창에서 엽니다. 초기에는 별도 도메인 구입 없이 제공 주소로 검사할 수 있습니다.

제가 이어서 수행할 개발·검증:

- 배포 설정·빌드 로그 진단, 필요한 저장소 설정 정리.
- `/`, `/archive`, 문서 직접 URL, 새로고침·Back·모바일 확인.
- Production 주소에 의도하지 않은 로그인 요구가 없는지 확인. 원본 공개 전까지 `noindex` 유지.

완료 조건: 개발 PC를 끄거나 클라우드 개발 세션을 종료해도 서비스 주소에 접속 가능. 현재 단계에서는 계획 기반 사이트이며 원본 열람은 아직 연결되지 않음.

### 단계 B — Supabase와 원본 준비

사용자가 할 일:

1. Supabase 계정과 프로젝트를 만듭니다. 주 독자가 한국·동아시아라면 제공 지역 중 가까운 지역을 검토합니다. Vercel의 원본 링크 발급 함수와 DB 지역 간 지연도 함께 봅니다.
2. 무료 테스트와 유료 운영 중 이번 단계에 사용할 요금제를 선택합니다. 결제·유료 전환은 사용자 계정에서 수행합니다.
3. 실제 연구 원문 S00–S12와 공개 여부를 준비합니다. 파일은 개발 세션에 제공하거나 관리자 권한으로 Supabase에 직접 올리는 경로 중 선택할 수 있습니다.
4. 비밀 키 값은 채팅에 보내지 않고 서비스의 환경 변수 설정에 입력합니다.

제가 이어서 수행할 작업:

- 버킷·테이블·RLS용 검토 가능한 설정/마이그레이션 작성.
- 원문 인벤토리·해시·중복·파일 형식 확인 및 PDF 변환 절차 정리.
- 개인정보가 있는 원본과 공개용 사본 구분, 사용자 공개 승인 상태 기록.
- 파일별 객체 경로·버전·프로젝트 연결 등록 및 복구용 파일 목록 내보내기.

완료 조건: 관리자 원본 보관 위치와 공개 가능 자산 목록이 확정되고, 비공개 항목은 익명으로 접근 불가. 자동 PDF 변환이 불가능한 HWP는 내용 확인 없이 대체본으로 채우지 않음.

### 단계 C — 원본 열람 기능과 배포

- 후속 버전에서 Supabase 자산 어댑터·서명 경로·원본 선택 UI 구현.
- 허용된 업로드 형식과 버킷 크기 제한 확인. 처음에는 PDF 및 지정 문서 형식만 허용하고 파일 확장자·MIME를 확인.
- 공개 상태·권리 검토·필수 메타데이터가 있는 자산만 게시.
- Vercel 프로젝트의 Root Directory를 후속 버전 폴더로 변경하고 서버 환경 변수 등록 후 재배포.
- 최초에는 원문 한 개로 끝까지 확인한 뒤 나머지 자료를 연결.

완료 조건:

- 공개 PDF는 로그인 없이 열리고 작성 원본 다운로드가 표시된 형식과 일치함.
- 비공개·철회·없는 자산 ID는 파일 링크를 발급하지 않음.
- 만료 링크는 사이트에서 재발급할 수 있음. 철회 후 신규 발급 차단, 기존 링크는 정해진 만료 시점까지 유효할 수 있음을 확인.
- 외부에서 버킷/경로를 바꿔 다른 파일을 서명할 수 없음.
- 익명 사용자의 업로드·수정·삭제 거부.
- 실제 API 응답과 클라이언트 번들에 비밀 키·비공개 문서 메타데이터 없음.
- Supabase 접속 실패 시 원본 오류 안내와 정적 HTML 읽기 경로 유지.

### 단계 D — 상시 운영과 정식 공개

- 기본 서비스 주소로 안정화한 뒤 필요하면 개인 도메인 연결.
- 공개할 콘텐츠와 개인정보 검토 완료 후 검색 노출·sitemap·canonical 전환.
- 사이트와 원본 열람 경로를 각각 주기적으로 점검.
- 사용량·트래픽·과금 알림 설정. DB뿐 아니라 Storage 파일 자체도 별도 백업하고 복원 시험.
- 오류 시 Vercel의 이전 정상 배포로 되돌릴 수 있게 배포 버전과 DB 변경 호환성 유지. 파일 버전은 덮어쓰지 않음.

## 7. 비용·상시 접속 정책

**무료 검증과 상시 운영은 구분합니다.**

- 무료 검증: 제공 범위 내에서 Vercel과 Supabase를 시험하고 기본 서비스 주소 사용. 실제 무료 조건·용량·업로드 제한·트래픽은 가입 시 확인.
- 상시 원본 열람: Supabase 공식 운영 문서는 Free Plan의 낮은 활동이 7일간 이어지면 프로젝트를 일시 중지할 수 있고, Pro에서는 inactivity 때문에 중지하지 않는다고 설명합니다. 그러므로 독자가 드문 연구 사이트에서 무료 플랜으로 원본의 상시 열람을 보장하지 않습니다.
- Vercel 요금제는 개인/상업 용도와 팀 구성, 트래픽, 함수 사용량을 확인해 선택합니다. 문서 다운로드는 Supabase가 담당하므로 Storage 용량과 전송량도 별도로 계산합니다.
- 월 비용은 원본 총용량·월 열람량·선택 요금제·지역·도메인 구입에 따라 결정됩니다. 현재 가격표를 확인하지 못한 상태에서 고정 무료 또는 특정 월 요금을 약속하지 않습니다.
- 규모 계산은 `원본+PDF 파생본+보존 버전의 총합`, 전송량은 `실제 열람 파일 크기×열람 횟수`를 기준으로 시작합니다. 실제 원문 파일이 없으므로 지금 임의 용량을 넣지 않습니다.

제안: 먼저 무료로 사이트/원문 한 개를 검증하고, 대외 제출·정식 운영 전에 휴면 없는 Supabase 운영 요금제와 백업을 확정합니다. 무료 프로젝트를 인위적인 keep-alive 요청으로 유지하는 것을 상시 운영 계획으로 삼지 않습니다.

## 8. Vercel과 Oracle의 역할 비교

| 기준                       | Vercel                                  | Oracle VM                                                      |
| -------------------------- | --------------------------------------- | -------------------------------------------------------------- |
| 현재 Next.js 사이트 시작   | GitHub 연동 배포와 프레임워크 기본 설정 | Node 런타임·프로세스 관리·리버스 프록시 등을 구성              |
| HTTPS·도메인               | 관리형 기능 이용                        | 인증서·프록시·갱신 운영 설계 필요                              |
| 업데이트·복구              | 커밋별 배포와 이전 정상 배포 활용       | OS/Node 업데이트, 배포 스크립트, 서비스 재시작, 복구 설계 필요 |
| 문서 변환·오래 걸리는 처리 | 함수 제한에 맞춰 별도 작업자 검토       | 장시간 배치 작업을 위한 후보                                   |
| 비용·가용성                | 선택 플랜·할당량 확인                   | 인스턴스 가용성·스토리지·네트워크·계정 정책 확인               |

Oracle의 무료 자원·특정 리전 VM 재고·장기 유지 조건은 이 계획에서 보장하지 않습니다. 현재 기능에는 Vercel+Supabase로 시작하고, 실제 변환 작업량이 확인되면 Oracle의 이점을 다시 평가합니다.

## 9. 사용자 계정에서만 진행할 항목

- Vercel/Supabase 로그인·계정 생성, GitHub 접근 허용.
- 요금제 선택·결제·도메인 구매.
- 실제 원문 제공, 각 파일의 공개 승인.
- 서비스 설정 화면의 비밀 키 입력과 최종 외부 배포 승인.

이후 구현을 진행할 때는 코드·설정·테스트 결과를 먼저 준비하고, 계정 연결·비용 발생·외부 공개에 필요한 단계만 구체적으로 안내합니다. 현재 단계에서 토큰이나 키 값을 채팅으로 요청하지 않습니다.
